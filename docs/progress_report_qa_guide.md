# 毕设进度报告「问答式」写作指南

结合本仓库的初代 Demo 代码与老师提供的报告模板，以下给出一个“自问自答式”填写思路。每个小节先写**提示问题**，再补上**简短回答**，既方便回顾进度，又能保证内容与代码一致。

> 使用前可先跑一次集成测试，确保数据与路径可复现：  
> ```bash
> PYTHONPATH=. python3 tests/test_end2end.py
> ```  
> 成功后会在 `output/bom/`、`output/manual/` 等目录生成样例输出，可直接引用到报告中。

---

## 1. 项目概述
- **Q：本次毕设解决什么问题？**  
  A：从自然语言设计需求到可制造的宜家家具方案，包含零件匹配、工程校验、CAD 与说明书自动生成。
- **Q：当前实现到什么程度？**  
  A：已完成端到端 Demo，覆盖意图解析→零件库检索→结构推理→工程校验→BOM/CAD/组装说明书生成，并有可跑通的集成测试。

## 2. 系统架构与关键模块
- **Q：整体架构如何？**  
  A：参照 `README.md` 的项目结构，核心模块位于 `core/`，数据模型在 `models/`，配置在 `config/`，前端入口为 `app.py`（Streamlit）。
- **Q：关键模块职责是什么？**  
  - `core/intent_parser.py`：GLM-4 解析设计意图，输出标准化 IR。  
  - `core/ikea_part_client.py`：访问本地 SQLite 零件库（真实宜家零件数据）。  
  - `core/structure_reasoner.py`：依据 IR 生成零件组合与结构方案。  
  - `core/engineering_validator.py`：承重、尺寸、可装配性、材料兼容性校验。  
  - `core/cad_generator.py`：用 CadQuery 生成 STEP 三维模型。  
  - `core/manual_generator.py`：输出 Markdown 组装说明书。

## 3. 数据与可重复性
- **Q：零件数据来源与说明？**  
  A：`data/ikea_parts.db` 来源于宜家官网公开数据，初始化脚本 `data/init_db.py` 可复现，当前收录 18 个关键零件；路径通过 `config/api_config.py` 的 `DB_PATH` 控制。
- **Q：如何保证不“幻觉”数据？**  
  A：零件检索全部来自本地数据库，`ikea_part_client` 禁止生成或补全不存在的零件。

## 4. 实验/运行记录
- **Q：本轮迭代做了哪些实验或验证？**  
  A：至少记录一次集成测试输出：运行命令、是否通过、生成的 BOM/说明书文件名。可附上 `output/bom/*.md` 或 `output/manual/*.md` 的摘要。
- **Q：是否跑通 Web UI？**  
  A：可说明 `streamlit run app.py` 是否成功，以及交互截图（如有）。

## 5. 当前进度与里程碑
- **Q：本阶段达成了哪些里程碑？**  
  A：完成端到端链路、数据库初始化、集成测试通过；已输出示例 BOM 与组装说明书。
- **Q：尚未完成/下一步计划？**  
  A：如“补充更多零件数据”“增加更多品类”“丰富单元测试”“接入真实 API Key 部署线上”等。

## 6. 风险与问题
- **Q：目前的主要风险或阻塞是什么？**  
  - LLM 依赖：需要配置 `ZHIPU_API_KEY` 才能进行真实意图解析。  
  - 数据规模：当前零件库仅 18 条，覆盖桌类场景，需扩充。  
  - 工程验证范围：承重/尺寸/材料规则可继续细化。  
- **Q：有哪些缓解措施？**  
  A：列出已采取或计划的对策，如“提供离线 IR 样例以便无 Key 评测”“增加数据抓取脚本”“补充校验规则”等。

## 7. 代码与提交记录
- **Q：本阶段关键提交/变更有哪些？**  
  A：引用本次迭代的提交要点（如新增配置、修复路径、文档补充），保持与 Git 历史一致。

## 8. 附录（可选）
- 集成测试命令与结果截图  
- 生成的 BOM、组装说明书、STEP 文件的存放路径  
- 关键配置项摘录：如 `config/constraint_config.py`（承重安全系数、材料兼容性等）

### 使用小贴士（写作时可复用的句式）
- “本阶段已完成 **端到端链路验证**，`tests/test_end2end.py` 通过，输出文件位于 `output/bom/` 与 `output/manual/`。”
- “零件数据全部来源于 **本地 SQLite 库**，路径由 `config/api_config.py` 的 `DB_PATH` 配置，确保 **无幻觉零件**。”
- “工程校验使用 `constraint_config.py` 中的 **1.2× 安全系数** 与 **材料兼容性表**，支持快速调参。”

按以上“问→答”方式填入老师的模板，即可确保报告内容与仓库代码保持一致，并突出可复现性与工程细节。
